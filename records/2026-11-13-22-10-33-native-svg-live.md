## Generation and vector checks

- Tool: built-in `image_gen`; output was PNG. No model/version/Flare/Sunburst identifier was returned. This verifies the native PNG-to-vector route, not direct SVG generation or an Images 2.6 API call.
- Subject: a pink tulip with green leaves and a yellow ribbon. Three PNG candidates and the original trace were preserved; the final vector uses candidate 3.
- The first transparent candidates contained soft shading/alpha halos. An initial unconstrained trace exceeded the palette limit and was not uploaded. A fresh flat image on white was traced using locally staged VTracer `1.0.0-alpha.4` with a fixed palette. The separate white background path was removed, and the complete visible geometry set the tight viewBox.
- Final SVG: `native-coral-tulip-ribbon-20261106232641.svg`; 3,720 bytes; 761 × 1262.13 units; four visible colors; six paths; no stroke attributes, raster payload, script, external link or foreignObject. SHA-256: `7cd825e35f5f7aae82bf24e852f37202c7f1a524a03705a56cbbaa19b0cf188a`.
- Visual inspection passed on the final vector render. Native generation runs through the remote tool; it exposes no local hardware selection. Local VTracer/XML finishing uses CPU and has no GPU execution option in the tested CLI.

The tracing command, relative to the live artifact directory, was:

```sh
tools/vtracer assets/source-imagegen/tulip-native-v3.png assets/source-svg/tulip-v3-traced-original.svg \
  --palette '#E57983,#F5B6AE,#4B8062,#F2CE70,#FFFFFF' \
  --hierarchical cutout --filter-speckle 64 --simplify 2 --path-precision 2 --optimize 2
```
