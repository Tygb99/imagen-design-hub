## Explicitly selected API workflows

Use these settings only with a user-selected API tool/client that actually supports them. This plugin provides instructions, not an API client. Recheck the official docs before a live request.

| Control | Use |
| --- | --- |
| `model` | `gpt-image-2.6-flare` for fast iteration; `gpt-image-2.6-sunburst` for demanding detail/edit precision. Compare on the actual task. |
| `quality` | `auto`, `low`, `medium`, `high`, `xhigh`, `max`. Controls detail/fidelity. Compare higher settings for final assets. |
| `complexity` | `low`, `medium`, `high`; omitted defaults to `high`. Try `low` for a focused edit, higher for complex layouts. Keep quality fixed when comparing. |
| `background` | For transparent raster output, use `transparent` with PNG or WebP and inspect decoded alpha. |

For markup edits, use `/v1/images/edits`: the original is the first input; `markup` is a separate transparent PNG overlay matching its oriented dimensions. Describe the change and what must remain fixed. Do not combine markup with `mask` or `prompt_rewriter`. Verify the annotation is absent from the result.

For SVG, use `/v1/images/generations`, `output_format="svg"`, `n=1`; decode the returned base64 into UTF-8 SVG. SVG output is unavailable on the edit endpoint and does not support streaming, partial images, `output_compression` or `prompt_rewriter`. Keep the returned source, then apply [SVG finishing and validation](../skills/svg/SKILL.md).

## Edit and series review

Inspect the target before editing. Reuse the accepted reference for variants, name each change, and preserve identity, geometry, palette, composition and alpha unless requested otherwise. Compare every revision with the original and review the complete series. Record prompts, references, returned model evidence and actual file measurements. Model quality/size controls do not guarantee DesignHub acceptance or replace project DPI targets.
