# Imagen Design Hub: 컬렉션

[English](SKILL.md)

DesignHub 컬렉션 한도 확인, 승인 요소 묶기, 컬렉션 등록·메타데이터 수정에 사용한다. 플러그인에 이 기능을 추가하라는 요청은 플러그인 수정 범위이며 실제 컬렉션을 새로 만들라는 요청이 아니다. 파일 업로드·요소 CSV 변경·심사 제출은 해당 작업도 요청됐을 때만 [upload-csv](../upload-csv/SKILL.ko.md)로 처리한다.

## 현재 상태 확인

설치된 Aside 스킬과 현재 가이드를 따른다. 해당하는 기존 탭에 연결해 계정을 확인하고 [컬렉션 관리](https://designhub.miricanvas.com/ko/collection/manage)와 [요소 관리](https://designhub.miricanvas.com/ko/element/manage)를 읽는다. 현재 화면에서 컨트롤을 찾는다. 브라우저 변경은 UI로 수행하고 로컬 도구는 목록 준비·다운로드 CSV 비교에 사용한다.

- 2026-10-21 관리 화면의 한도는 컬렉션 400개, 컬렉션당 요소 30개였다. 계획 전에 현재 한도를 읽는다. 과거 관측값을 영구 상수로 취급하지 않는다.
- 처음 목록에는 최근 등록분만 보인다. 전체 개수나 남은 자리를 계산하기 전에 날짜·검색 범위를 넓힌다. 필터된 목록의 0개는 계정 전체가 비었다는 근거가 아니다.
- 현재 [제작 조건](https://slashpage.com/designhub-guide/xjqy1g2vw99edm6vd54z)을 확인한다. 공개 요소 최소 6개, PNG 요소·SVG 요소·GIF 애니 중 동일 타입, 공통 스타일·주제가 필요하며 요소 하나는 컬렉션 하나에만 들어간다. 컬렉션에는 별도 심사 대기가 없다.
- 승인·노출·컬렉션 소속은 현재 화면으로 확인한다. 과거 CSV 파일명의 “approved”나 “waiting”은 현재 상태를 증명하지 않는다. 제출 예정·심사 대기·거부·비공개·지원하지 않는 항목은 계획에서 제외한다.

## 중복 없이 묶기

1. 대화·로컬 목록·현재 화면으로 대상 묶음을 식별하고 계정의 무관한 요소를 제외한다. 대상을 특정할 수 없을 때만 등록 전에 필요한 범위를 묻는다.
2. 원본 `fileName`, 다운로드 CSV의 `uniqueId`, UI의 숫자 요소 ID를 대응시킨다. 세 값은 서로 다른 식별자다. 다운로드 표기를 보존하고, 확장자 유무를 정규화한 매칭은 하나로 확정될 때만 사용한다. 모호한 이름을 목록 순서로 연결하지 않는다.
3. 관련 날짜 전체에서 대상 ID의 기존 컬렉션 소속을 확인한다. 이름이나 최근 30일 목록만 보지 않고 저장된 구성과 비교한다. 의도한 ID 집합과 같은 컬렉션이 있으면 확인해 재사용한다. 다른 기존 컬렉션에 속한 요소는 사용자가 이동을 요청하지 않으면 그대로 둔다. 소속을 확인할 수 없는 항목은 미소속으로 가정하지 않고 미확인으로 보고한다.
4. 자격을 갖춘 미소속 요소를 먼저 타입, 다음으로 주제·스타일별로 나눈다. 미리보기를 확인한다. 같은 키워드만으로 그림의 일관성을 판단하지 않는다. 계획 안에서 각 요소는 한 묶음에만 넣는다.
5. 사용자의 묶음 크기를 현재 최소·최대 한도 안에서 따른다. 별도 지정이 없으면 `k = ceil(n / 최대값)`으로 묶음 수를 정하고 `n >= k * 최소값`일 때 균등하게 나눈다. 한도가 6~30개라면 관련 요소 100개는 25개씩 4묶음, 31개는 16개와 15개로 나눌 수 있다. 1~5개짜리 묶음을 남기거나 무관한 요소로 채우지 않는다. 유효한 컬렉션을 만들 수 없는 나머지는 보고한다.
6. 필요한 새 묶음 수를 확인된 빈 컬렉션 자리와 비교한다. 자리가 부족하면 초과분을 계획 상태로 남겨 보고한다. 기존 컬렉션을 숨기거나 교체해 자리를 만들지 않는다.

중단 후 이어갈 수 있도록 등록 전에 계획한 ID를 기록한다. 대상 컬렉션을 만들라는 명시적 요청은 그 묶음의 등록을 포함하므로 같은 승인을 다시 묻지 않는다. 한도만 묻는 요청에는 등록하지 않는다.

## 제목과 키워드

사용자가 정한 언어·명명 규칙을 따른다. 한국어 제목은 그룹 전체에 맞는 속성으로 `색 + 스타일 + 모양 + 주제어 + 위치/역할` 순서의 짧은 명사구를 쓴다. 색은 한글로 쓰고 공통되지 않는 속성은 생략한다. 관련 묶음을 구분할 때만 두 자리 번호를 붙인다. 예: `분홍색 3D 아크릴 글자 블랙프라이데이 타이틀 01`.

기본은 현재 UI 한도 안에서 중복 없는 한국어 검색어 정확히 25개다. 별도 개수·언어 요청이 있으면 따른다. 공통 주제·별칭 → 주제와 역할의 조합 → 어울리는 사용처·시즌 → 스타일·재질 순으로 쓴다. 한 색이 컬렉션을 대표할 때만 대표 색상 키워드 1개를 제목과 다른 표기(예: `분홍색` → `핑크`)로 넣는다. 각도는 그룹에 맞을 때만 넣는다. 개별 요소 키워드의 합집합을 그대로 복사하지 않는다. 단독 `아이콘`·`장식`·`데코`·`오브젝트`, `PNG`·`투명배경` 같은 파일 속성, 제작 용어, 오타는 제외한다. 검색어 선택은 [키워드 지침](../../references/keyword-generation.ko.md)도 참고하되 기본 개수는 이 컬렉션 규칙을 따른다.

## Aside에서 등록

1. 요소 관리에서 묶음의 정확한 항목을 선택하고 선택 개수를 확인한다. 목록은 가상 스크롤을 사용한다. 관측한 카드를 화면으로 이동한 뒤 새로 렌더링된 카드를 읽는다. 첫 선택이나 패널 크기 변경 후 열과 표시 범위가 바뀔 수 있으므로 다시 확인한다. DOM 순서를 영구 식별자로 쓰지 않는다.
2. 카드의 시각적 컨트롤 아래 네이티브 체크박스가 숨겨져 있으면 카드 DOM을 읽어 해당 체크박스를 찾는다. 일반 선택으로 접근할 수 없을 때만 확인한 체크박스에 `check({force:true})`를 쓴다. 크기 측정용 중복 카드는 가시성이나 확인한 DOM으로 구분한다. 관측된 UI에서는 `.last()`가 맞았지만 모든 화면에 적용할 선택자 규칙은 아니다.
3. `컬렉션 만들기`를 열고 타입·개수를 확인한 뒤 `다음`으로 간다. 등록 패널의 요소 ID를 계획한 집합과 비교한다. 숫자 요소 ID 칸에 CSV의 `uniqueId`를 붙여 넣지 않는다.
4. 이름과 쉼표로 구분한 키워드를 입력한다. 관측된 키워드 입력칸은 쉼표를 눌러야 확정됐고 입력만 하거나 Enter를 누르는 것으로는 부족했다. 필요하면 끝으로 이동해 쉼표를 누른 뒤 키워드 칩과 개수를 확인한다. 이름 길이·키워드 한도는 현재 입력칸을 따른다.
5. 이름·키워드·ID를 기록한 뒤 `등록`을 한 번 누르고 결과를 남긴다. 시간 초과나 불분명한 응답이면 재시도 전에 관리 화면에서 해당 이름·ID 집합이 저장됐는지 확인한다. 빠진 묶음만 이어서 등록한다. 부재를 확인한 묶음도 최초 시도 이후 2회 재시도에 실패하면 보고하고 독립적인 나머지 묶음을 처리한다.
6. 저장된 컬렉션을 각각 다시 연다. 부여된 컬렉션 ID/key, 정확한 이름, 키워드 목록·개수, 요소 ID 집합·개수, 화면 상태를 확인한다. 성공 알림만으로 완료 처리하지 않는다. 카드가 선택돼도 상세가 닫혀 있으면 화면에서 확인한 정보 패널 버튼을 사용한다. 관측된 UI에서는 카드 이미지 클릭이 가능했고 잘린 제목 텍스트 클릭은 불안정했다.

## 기존 컬렉션 수정

부여된 ID/key로 컬렉션을 특정해 상세를 연다. 현재 구성·이름·키워드·노출 상태를 기록한다. `메타데이터 수정`에서 요청한 필드만 바꾸고 저장한 뒤 다시 열어 비교한다. 이름·키워드만 수정하는 요청에서는 구성과 노출 상태를 보존한다. 메타데이터 수정을 위해 컬렉션을 다시 만들지 않는다.

[관리 가이드](https://slashpage.com/designhub-guide/3p4kj92ynppykm57q1x8)에 따르면 컬렉션은 삭제할 수 없고 비공개·비활성 여부는 개별 요소의 노출 상태와 별개다. 노출 변경은 요청됐을 때만 처리하고 관리자가 비활성화한 컬렉션을 재활성화하려 하지 않는다. 현재 UI에서 구성 수정이 지원되지 않으면 중복 대체 컬렉션을 만들지 말고 한계를 보고한다.

## 증거와 결과 전달

요소 업로드 메타데이터와 분리해 현재 작업 폴더에 UTF-8 CSV를 보관한다.

- `collections.csv`: `collectionId,collectionKey,collectionName,contentType,elementCount,keywordCount,keywords,status,verifiedAt`
- `collection-members.csv`: `collectionId,fileName,uniqueId,elementId`

확인 전 계획은 별도 로컬 파일에 둔다. 모르는 ID·상태는 만들어 넣지 않고 빈칸으로 둔다. 이 파일은 추적용이며 DesignHub 업로드 양식이 아니다. 식별자를 보존하고 화면 증거에는 시각을 붙인다. 개인 계정 기록이나 로그인 정보를 플러그인에 포함하지 않는다.

계획과 저장된 ID 집합을 비교하고 컬렉션 간 요소 ID 중복을 확인한다. 의도한 각 항목을 등록됨·기존 소속 있음·부적격·미확인 중 하나로 집계한다. 확인한 컬렉션·요소 수, 메타데이터 상태, 남은 항목을 보고한다. DesignHub 등록·상태와 미리캔버스 편집기에서의 실제 사용 가능 여부를 구분하며 후자는 요청됐을 때 별도로 확인한다. 사용자가 볼 수 있도록 컬렉션 관리 페이지를 열어 둔다.
